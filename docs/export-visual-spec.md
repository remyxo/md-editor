# 导出视觉规范对照（编辑器 / HTML / PDF / DOCX）

四个「面」各自维护一套 CSS 或 OOXML 样式，同一份文档在不同产物里的观感因此可以
分叉。本文把**实际数值**逐项列出，并标注判定：哪些是**媒介差异**（必须各自维护，
不该强行统一），哪些是**同一规范抄两遍后漂移**（应当收敛到单一来源）。

写本文的目的：改任何一项之前先在这里定调，避免「为统一而统一」又把打印版式
改坏。**判定为漂移的项，改前请先读 [`pdf-header-footer-layout.md`](pdf-header-footer-layout.md)**
（打印侧版式与分页约束）与 [`cross-platform-monospace-font.md`](cross-platform-monospace-font.md)
（等宽字族平台差异）。

## 四个面

| 面 | 样式载体 | 说明 |
|---|---|---|
| 编辑器 | `src/resources/web/editor.css` | 用户写作时看到的即时观感 |
| HTML 导出 | `HtmlExporter::bodyCss(theme)`（亮/暗两套） | 屏幕阅读/浏览器打印 |
| PDF 导出 | `PdfExporter` 基础 CSS（渲染页模板） | 固定亮色打印；nativeHf 与 paged 两路共用 |
| DOCX 导出 | `DocxExporter` 的 OOXML（`w:rPr`/`w:pPr`/底纹/边框） | Word 打开后的观感；单位为半磅/缇/EMU |

## 对照表（数值取自代码，非推测）

### 字号基准（em 解析的坑，2026-09-21 定案）

**任何包装元素都可能改变 `em` 的解析基准。** nativeHf 把正文整篇包进包装表单元格
`<td id="hfcell">`，基础 CSS 的 `th,td{...font-size:10pt}`（当时值；2026-09-24 起
th,td 为 11pt，教训保留）因而作用于它 ⇒ 单元格内
一切 `em` 相对值按 **10pt** 而非设计基准 11pt 解析：`h1{1.7em}` 得 17pt（应 18.7）、
行内 `code{0.9em}` 得 9pt（应 9.9）。绝对值字号（页脚 9pt）不受影响，
所以症状表现为**只有标题差一档**——实测有无脚注两份 PDF 的 h1/h2/h3 高宽一律差
1.100×，表格与页脚 1.000×。`th,td` 自 2026-09-24 起为 11pt（与正文一致，
em 基准同 11pt）。

定案：`#hfcell{font-size:11pt;...}` 显式钉回基准（id 特异性高于 `th,td`），两路一致。
**新增包装层（表格单元格/容器 div）时，必须显式声明字号**，否则内部相对字号静默漂移。

### 标题阶梯

| 级 | 编辑器 | HTML 导出 | PDF | DOCX（半磅） | 判定 |
|---|---|---|---|---|---|
| h1 | 2em / 700 | 2em + 下划线 / 600 | **1.7em** 无下划线 | 37 = 18.5pt（≈1.7em 半磅近似） | **已对齐 PDF**（2026-09-24，行高/边距同收敛） |
| h2 | 1.5em / 700 | 1.5em + 下划线 / 600 | **1.3em** 无下划线 | 29 = 14.5pt（≈1.3em） | **已对齐 PDF**（2026-09-24，行高/边距同收敛） |
| h3 | 1.25em / 600 | 1.25em / 600 | **1.1em** | 24 = 12pt（≈1.1em） | **已对齐 PDF**（2026-09-24，行高/边距同收敛） |
| h4–h6 | 1.1 / 1 / 0.9em | 无独立规则 | 无规则 | 24 = 12pt | 媒介差异（Word 需显式给每级字号） |

PDF 的紧凑阶梯可解释为打印密度取舍，但**编辑器与 HTML 一致、PDF 与 DOCX 各自
一套**，三套数值意味着任何一次调整都要改三处。2026-09-24 起DOCX h1–h3 已与 PDF 逐值收敛（字号半磅近似 + 行高/边距全缇值，见行距行），三套变两套（屏幕侧编辑器/HTML 一套、打印侧 PDF/DOCX 一套）；h4–h6 保留 Word 显式字号。

## 判定汇总

- **媒介差异（各自维护，不统一）**：正文字号基准、暗色主题、圆角、打印侧更紧的
  内边距、斑马纹、Word 的单位与页眉页脚机制、PDF 覆盖层的 `rgb(102,102,103)` 签名色。
- **疑似漂移（建议收敛）**：标题阶梯（h1–h3 已对齐 PDF，h4–h6 保留）、引用块边框粗细与文字色、行内 code
  三项、代码块字号（DOCX）、表格边框色（三套）。
- **待你裁决**：DOCX 表头底色 `D9E2F3`（浅蓝）、页眉页脚灰
  `#666` vs `#808080`。（DOCX 行距已于 2026-09-24 定案对齐 1.6，移出本单）

## 改任一项的验证成本（务必照做）

1. **PDF**：改后须重跑「页数 + 页眉/页脚墨迹落点 + 分页校验」（后两者由
   `PdfExporter` 成品校验自动拦截，但页数与落点需人工对照
   [`pdf-header-footer-layout.md`](pdf-header-footer-layout.md) 的实测表）；字号/
   行距改动会直接改变分页，可能引起页数变化。
2. **DOCX**：必须按 [`CLAUDE.md`](../CLAUDE.md) 与项目记忆的既定流程做 **macOS
   Word 双击验证**（WPS/LibreOffice 宽容，测不出 schema 违规）。
3. **HTML**：改 `bodyCss` 后重载产物截图对照；列宽归一脚本的测量样式跟随单元
   字号，改字号须重跑表格列宽核对（见 `HtmlExporter::tableColumnNormalizeScript`）。
4. **编辑器**：`editor.css` 改动影响写作观感，需与上面三者分别对照，不是它们的
   从属项。
